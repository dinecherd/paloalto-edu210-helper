Configurer proprement,
du premier coup.

Les règles d'or pour une rulebase lisible et sûre : comment créer une règle de sécurité pas à pas (GUI et CLI), publier un serveur en NAT, appliquer les profils, nommer les objets, durcir le management et garder des logs exploitables.

Les règles d'or d'une rulebase

PAN-OS évalue les règles de haut en bas et applique la première qui correspond. L'ordre, la précision et les profils font toute la différence.

  • ✓Utiliser App-ID, pas les ports. Remplir Application (ex. ssl, web-browsing, dns) au lieu de any + service TCP/443.
  • ✓Service = application-default : l'application n'est autorisée que sur ses ports standards. Évite le contournement par port non standard.
  • ✓Du plus précis au plus général. Les règles spécifiques (un serveur, un groupe d'utilisateurs) en haut, les règles larges en bas.
  • ✓Un profil de sécurité sur chaque règle allow (via un Security Profile Group) : AV, Anti-Spyware, Vulnérabilités, URL, File Blocking, WildFire.
  • ✓Log at Session End activé + un Log Forwarding Profile vers le syslog/SIEM ou Panorama.
  • ✓Nom, description et tag sur chaque règle : qui l'a demandée, pourquoi, n° de ticket, date.
  • ✓Activer le log sur interzone-default (Policies › Security › Override) pour voir ce qui est bloqué.
  • ✓Filtrer par utilisateur/groupe (User-ID) quand c'est possible plutôt que par plage IP.
  • ✕Jamais de règle any → any / any / allow. Même « temporaire » : elle reste toujours.
  • ✕Pas de service any avec une application précise : l'application passerait sur n'importe quel port.
  • ✕Pas de règles en double ou masquées (shadowed) : PAN-OS les signale au commit, corrige-les.
  • ✕Ne pas autoriser le management (ssh, https du pare-feu) depuis Untrust.

Exemple : créer une règle de sécurité pas à pas

Besoin : autoriser les postes du LAN (192.168.1.0/24) à naviguer sur Internet en HTTP/HTTPS, avec inspection complète et logs.

1

Créer l'objet adresse

Objects › Addresses › Add

Name : NET-LAN-Users · Type : IP Netmask · 192.168.1.0/24 · Tag : LAN

2

Préparer le groupe de profils

Objects › Security Profile Groups › Add

Name : PG-Default · Antivirus default · Anti-Spyware strict · Vulnerability strict · URL default · File Blocking basic file blocking · WildFire default.

AstuceNomme le groupe default : il sera appliqué automatiquement à toutes les nouvelles règles.
3

Créer la règle — onglet General

Policies › Security › Add

Name : LAN-to-Internet-Web · Rule Type : universal · Description : « Navigation web des postes LAN – ticket #1234 » · Tag : LAN

4

Onglets Source / Destination

Source : Zone LAN · Address NET-LAN-Users · User any (ou un groupe AD si User-ID est actif)

Destination : Zone WAN · Address any

5

Onglets Application / Service-URL Category

Application : web-browsing, ssl (pas any)

Service : application-default · URL Category : any (le filtrage se fait via le profil URL)

6

Onglet Actions

Action : Allow · Profile Type : Group → PG-Default · ☐ Log at Session Start · ☑ Log at Session End · Log Forwarding : LF-Default

7

Placer la règle, valider et commiter

Glisse la règle au-dessus de Deny-All-Log, puis Commit › Preview Changes › Validate › Commit.

La même chose en CLI

# mode configuration
configure

# 1. objet adresse + tag
set tag LAN color color3
set address NET-LAN-Users ip-netmask 192.168.1.0/24
set address NET-LAN-Users tag LAN

# 2. groupe de profils
set profile-group PG-Default virus default spyware strict vulnerability strict url-filtering default file-blocking "basic file blocking" wildfire-analysis default

# 3-6. règle de sécurité
set rulebase security rules LAN-to-Internet-Web from LAN to WAN source NET-LAN-Users destination any source-user any application [ web-browsing ssl ] service application-default category any action allow
set rulebase security rules LAN-to-Internet-Web profile-setting group PG-Default
set rulebase security rules LAN-to-Internet-Web log-start no log-end yes log-setting LF-Default
set rulebase security rules LAN-to-Internet-Web tag LAN description "Navigation web des postes LAN - ticket #1234"

# 7. position + commit
move rulebase security rules LAN-to-Internet-Web before Deny-All-Log
commit

Règle de blocage finale avec log

set rulebase security rules Deny-All-Log from any to any source any destination any application any service any action deny log-end yes
# ou : activer le log sur la règle par défaut interzone
set rulebase default-security-rules rules interzone-default action deny log-end yes

Vérifier

# quelle règle s'applique à ce flux ?
test security-policy-match from LAN to WAN source 192.168.1.50 destination 8.8.8.8 protocol 6 destination-port 443 application ssl

# sessions en cours depuis un poste
show session all filter source 192.168.1.50

# compteurs d'utilisation des règles
show rule-hit-count vsys vsys-name vsys1 rule-base security rules all

NAT : les pièges à éviter

La règle d'or : NAT = adresses pré-NAT, zone selon la route. La règle de sécurité utilise les IP pré-NAT et la zone post-NAT.

CasRègle NATRègle de sécurité
Source NAT (LAN → Internet)From LAN To WAN · Dynamic IP and Port · interface ethernet1/1From LAN To WAN · source 192.168.1.0/24
Destination NAT (publication serveur)From WAN To WAN · dst 203.0.113.20 → 10.10.20.10From WAN To DMZ · dst 203.0.113.20 (IP publique !)
  • ✓Préférer DIPP sur l'interface pour la sortie Internet ; un pool d'IP au-delà de ~64 000 sessions simultanées par IP.
  • ✓Bi-directionnel uniquement pour du 1:1 statique ; sinon deux règles distinctes.
  • ✓Prévoir l'U-turn si les utilisateurs internes accèdent au serveur via son IP publique.
  • ✕Ne pas mettre la zone DMZ en destination de la règle DNAT : la zone de destination NAT est celle de l'IP publique (WAN).
# Source NAT sortie Internet
set rulebase nat rules SNAT-LAN-Internet from LAN to WAN source NET-LAN-Users destination any service any source-translation dynamic-ip-and-port interface-address interface ethernet1/1

# Destination NAT : publication du serveur web
set address SRV-WEB-01 ip-netmask 10.10.20.10/32
set address PUB-WEB-01 ip-netmask 203.0.113.20/32
set rulebase nat rules DNAT-WEB-01 from WAN to WAN source any destination PUB-WEB-01 service service-https destination-translation translated-address SRV-WEB-01

# règle de sécurité associée (IP pré-NAT, zone post-NAT)
set rulebase security rules WAN-to-DMZ-Web from WAN to DMZ source any destination PUB-WEB-01 application [ ssl web-browsing ] service application-default action allow profile-setting group PG-Default log-end yes

Profils de sécurité

Une règle allow sans profil laisse passer les menaces. Applique un groupe de profils à toutes les règles qui autorisent du trafic.

ProfilRecommandation
AntivirusAction reset-both sur tous les décodeurs (http, smtp, imap, pop3, ftp, smb). WildFire inline ML activé.
Anti-SpywareBasé sur strict · DNS Security + DNS sinkhole (IPv4 sinkhole.paloaltonetworks.com) pour repérer les postes infectés.
VulnerabilityBasé sur strict : reset-both pour critical/high/medium, défaut pour low/info.
URL FilteringBloquer malware, phishing, command-and-control, grayware, newly-registered-domain ; alert sur le reste pour la visibilité.
File BlockingBloquer les exécutables (exe, dll, bat, ps1…) depuis Internet, sauf exceptions justifiées.
WildFireEnvoyer any application / any type de fichier ; mises à jour WildFire en temps réel.
DécryptageSans déchiffrement SSL, les profils ne voient que ~10 % du trafic. Mets en place un SSL Forward Proxy en excluant les catégories sensibles (santé, finance, gouvernement) et les applis à certificate pinning.

Objets & convention de nommage

Une convention claire rend la rulebase lisible par toute l'équipe et facilite la migration vers Panorama.

TypeConventionExemple
HôteSRV- / PC- + rôle + n°SRV-WEB-01
RéseauNET- + zone/usageNET-LAN-Users
IP publiquePUB- + servicePUB-WEB-01
Groupe d'adressesGRP- + usageGRP-DNS-Internes
ServiceSVC- + proto + portSVC-TCP-8443
Règle sécuritéSource-to-Dest-UsageLAN-to-Internet-Web
Règle NATSNAT- / DNAT- + cibleDNAT-WEB-01
ProfilsPG- (groupe), AV-, AS-, VP-, URL-PG-Default
  • ✓Tags par zone/usage avec couleur pour filtrer la rulebase d'un clic (Group Rules by Tag).
  • ✓Groupes d'adresses dynamiques (DAG) basés sur les tags pour les environnements qui bougent (VM, cloud).
  • ✓EDL (listes dynamiques externes) pour les IP/URL malveillantes, mises à jour automatiquement.
  • ✕Pas d'IP en dur dans les règles : toujours un objet nommé.
  • ✕Supprimer les objets inutilisés régulièrement (Objects › filtre « Unused »).

Durcir le management

L'interface de management est la cible n°1 : elle ne doit jamais être exposée sur Internet.

  • ✓Management sur un réseau dédié (VLAN d'admin / bastion), avec Permitted IP restreintes.
  • ✓Désactiver HTTP et Telnet, ne garder que HTTPS et SSH.
  • ✓Comptes nominatifs via LDAP/RADIUS/TACACS+ + MFA ; compte admin local renommé ou mot de passe fort coffré.
  • ✓Admin roles au moindre privilège (lecture seule pour le support N1).
  • ✓Complexité de mot de passe et verrouillage après échecs ; bannière de connexion légale.
  • ✓Interface Management Profile sur les interfaces de données : uniquement ping si nécessaire, jamais sur la zone Untrust.
  • ✓Rester sur une version PAN-OS « preferred » et suivre les avis de sécurité (security.paloaltonetworks.com).
set deviceconfig system permitted-ip 10.0.99.0/24
set deviceconfig system service disable-http yes disable-telnet yes
set mgt-config password-complexity enabled yes minimum-length 12 minimum-uppercase-letters 1 minimum-numeric-letters 1 minimum-special-characters 1
set deviceconfig system login-banner "Acces reserve au personnel autorise. Toute connexion est journalisee."
set network profiles interface-management-profile MGMT-Ping-Only ping yes

Logs, mises à jour & sauvegardes

Logs

  • ✓Log at Session End sur toutes les règles ; Session Start uniquement pour du dépannage ponctuel (charge CPU).
  • ✓Log Forwarding Profile vers Panorama / syslog / SIEM pour traffic, threat, URL, WildFire.
  • ✓NTP configuré : sans horodatage fiable, les logs sont inexploitables.
  • ✓Alertes e-mail/SNMP sur les événements critiques (HA, menaces critical, échec de commit).
