Comment le pare-feu choisit une règle

PAN-OS lit la rulebase de haut en bas et applique la première règle dont tous les critères correspondent : zones, adresses, utilisateur, application. Les suivantes ne sont jamais lues. Choisis un flux et regarde.

▶ Démo interactive · first match

Les règles d'or

✓ À faire

  • ✓App-ID, pas les ports. ssl, web-browsing, dns… au lieu de any + TCP/443.
  • ✓Service application-default : chaque appli uniquement sur ses ports standards.
  • ✓Du plus précis au plus général : règles spécifiques en haut, larges en bas.
  • ✓Un groupe de profils sur chaque allow (AV, Anti-Spyware, Vuln, URL, File, WildFire).
  • ✓Log at Session End + Log Forwarding vers syslog/SIEM/Panorama.
  • ✓Nom, description, tag sur chaque règle : qui, pourquoi, n° de ticket.
  • ✓User-ID : autoriser des groupes AD plutôt que des plages IP.

✕ À éviter

  • ✕Jamais de any → any / allow, même « temporaire ».
  • ✕Pas de service any avec une appli précise : elle passerait sur tous les ports.
  • ✕Pas de règles masquées (shadowed) : PAN-OS les signale au commit.
  • ✕Pas d'accès management (ssh, https du pare-feu) depuis Untrust.
  • ✕Pas de log at Session Start en permanence : charge CPU inutile.
  • ✕Pas de règle désactivée qui traîne : supprime ou documente.
Pourquoi bloquer QUIC ?QUIC (UDP/443) chiffre tout et échappe au décryptage SSL et au filtrage URL. Bloqué, le navigateur revient tout seul en TLS/TCP, que le pare-feu sait inspecter.

Construire une règle de sécurité, pas à pas

Besoin client : les postes du LAN (192.168.1.0/24) naviguent sur Internet en HTTP/HTTPS, avec inspection complète et logs. Suis l'écran PAN-OS à gauche : la règle se construit à droite, la CLI s'écrit en dessous.

📋 Ta règleen construction


        

        

          
          
          
          
          
        

      


      

        ⌨️ Toute la CLI d'un coup + règle de refus + vérifications
        

          

# mode configuration
configure

# objet adresse + tag
set tag LAN color color3
set address NET-LAN-Users ip-netmask 192.168.1.0/24
set address NET-LAN-Users tag LAN

# groupe de profils
set profile-group PG-Default virus default spyware strict vulnerability strict url-filtering default file-blocking "basic file blocking" wildfire-analysis default

# règle de sécurité
set rulebase security rules LAN-to-Internet-Web from LAN to WAN source NET-LAN-Users destination any source-user any application [ web-browsing ssl ] service application-default category any action allow
set rulebase security rules LAN-to-Internet-Web profile-setting group PG-Default
set rulebase security rules LAN-to-Internet-Web log-start no log-end yes log-setting LF-Default
set rulebase security rules LAN-to-Internet-Web tag LAN description "Navigation web des postes LAN - ticket #1234"

# règle de refus finale avec log
set rulebase security rules Deny-All-Log from any to any source any destination any application any service any action deny log-end yes

# position + commit
move rulebase security rules LAN-to-Internet-Web before Deny-All-Log
commit

# vérifier : quelle règle s'applique à ce flux ?
test security-policy-match from LAN to WAN source 192.168.1.50 destination 8.8.8.8 protocol 6 destination-port 443 application ssl
show session all filter source 192.168.1.50
show rule-hit-count vsys vsys-name vsys1 rule-base security rules all

NAT : suivre le paquet

      
La règle d'or : la politique NAT et la politique de sécurité sont évaluées avec les adresses d'origine (pré-NAT). La traduction n'a lieu qu'à la sortie. Seule la zone de destination de la règle de sécurité est post-NAT.


      

        

          

            
            
          

          
          
          
          
        

        
        
    
      
    

      
    Le tableau à retenir
    
      
    
        
    CasRègle NATRègle de sécurité
    
        
          
    Source NAT (LAN → Internet)From LAN To WAN · Dynamic IP and Port · interface ethernet1/1From LAN To WAN · source 192.168.1.0/24
    
          
    Destination NAT (publication)From WAN To WAN · dst 203.0.113.20 → 10.10.20.10From WAN To DMZ · dst 203.0.113.20 (IP publique !)
    
            
      
    
      
      
        
    • ✓DIPP sur l'interface pour la sortie Internet ; un pool d'IP au-delà de ~64 000 sessions simultanées par IP.
      • 
        
    • ✓Bi-directionnel seulement pour du 1:1 statique, sinon deux règles distinctes.
      • 
        
    • ✓Prévoir l'U-turn si les utilisateurs internes joignent le serveur par son IP publique.
      • 
        
    • ✕Pas de zone DMZ dans la règle DNAT : sa zone de destination est celle de l'IP publique (WAN).
      • 
      
    
      
    
        

    # Source NAT sortie Internet
set rulebase nat rules SNAT-LAN-Internet from LAN to WAN source NET-LAN-Users destination any service any source-translation dynamic-ip-and-port interface-address interface ethernet1/1

# Destination NAT : publication du serveur web
set address SRV-WEB-01 ip-netmask 10.10.20.10/32
set address PUB-WEB-01 ip-netmask 203.0.113.20/32
set rulebase nat rules DNAT-WEB-01 from WAN to WAN source any destination PUB-WEB-01 service service-https destination-translation translated-address SRV-WEB-01

# règle de sécurité associée (IP pré-NAT, zone post-NAT)
set rulebase security rules WAN-to-DMZ-Web from WAN to DMZ source any destination PUB-WEB-01 application [ ssl web-browsing ] service application-default action allow profile-setting group PG-Default log-end yes

    Et le décryptage ?Sans déchiffrement SSL, les profils ne voient qu'une petite partie du trafic, puisque l'essentiel du web est en HTTPS.     Durcir le management
    
      
    L'interface de management est la cible n°1. Chaque couche de protection arrête un type d'accès différent : regarde qui passe et qui rebondit.
    
      
    
        ▶ Accès à l'interface de management
        
    👩‍💻 Admin IT10.0.99.10 · HTTPSHTTPS🛡️✓ autoriséIP permise + HTTPS
    
        
    👩‍💻 Admin IT10.0.99.10 · TelnetTELNET🛡️✕ refuséTelnet désactivé
    
        
    🕵️ Internet45.83.64.1 · HTTPSHTTPS🛡️✕ refuséhors permitted-ip
    
        
    🕵️ Internet→ IP WAN · SSHSSH🛡️✕ refusépas de profil mgmt sur WAN
    
      
    
      
    Les couches de protection
    
      
    
        
    1Réseau dédié : VLAN d'admin ou bastion, jamais exposé sur Internet.
    
        
    2Permitted IP : seules les IP d'admin peuvent joindre l'interface.
    
        
    3Services : HTTP et Telnet désactivés, HTTPS et SSH uniquement.
    
        
    4Comptes nominatifs LDAP/RADIUS/TACACS+ + MFA, admin roles au moindre privilège.
    
        
    5Mots de passe : complexité, verrouillage après échecs, bannière légale.
    
        
    6Interfaces de données : profil de management limité à ping, jamais sur Untrust.
    
        
    7Version PAN-OS « preferred » et suivi des avis sur security.paloaltonetworks.com.
    
      
    
      
    
        

    set deviceconfig system permitted-ip 10.0.99.0/24
set deviceconfig system service disable-http yes disable-telnet yes
set mgt-config password-complexity enabled yes minimum-length 12 minimum-uppercase-letters 1 minimum-numeric-letters 1 minimum-special-characters 1
set deviceconfig system login-banner "Acces reserve au personnel autorise. Toute connexion est journalisee."

        ▶ Où partent les logs
        
      
    

      
    
        
    
          
    📜 Logs
    
          
      
            
    • ✓Log at Session End partout ; Session Start pour le dépannage ponctuel uniquement.
      • 
            
    • ✓Log Forwarding Profile vers Panorama / syslog / SIEM (traffic, threat, URL, WildFire).
      • 
            
    • ✓NTP configuré : sans horodatage fiable, les logs ne valent rien.
      • 
            
    • ✓Alertes sur les événements critiques (HA, menaces critical, échec de commit).
      • 
          
    
        
    
        
    
          
    💾 Sauvegardes & changements
    
          
      
            
    • ✓Exporter la config avant chaque changement important et chaque montée de version.
      • 
            
    • ✓Preview Changes + Validate avant chaque commit, avec une description claire.
      • 
            
    • ✓Revue trimestrielle : règles sans hit, règles désactivées, objets inutilisés.
      • 
          
    
        
    
      
    
      
    
        

    set deviceconfig system update-schedule threats recurring every-30-mins at 5 action download-and-install
set deviceconfig system update-schedule anti-virus recurring hourly at 10 action download-and-install
set deviceconfig system update-schedule wildfire recurring real-time
